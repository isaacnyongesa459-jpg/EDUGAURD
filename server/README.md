# EduGuard backend

Privacy-first school digital safety API built with Node.js, Express, PostgreSQL and Socket.IO. The current extension reports domain-level navigation metadata and approximate duration/status/category. The service must never collect passwords, keystrokes, private messages, files, audio or video. Full URLs are not retained; URL capture is disabled in the extension policy and rejected by current rule creation. Disclose monitoring clearly to students and guardians.

## Local setup

Requires Node.js 20+ and PostgreSQL. Copy `server/.env.example` to `server/.env`, set a strong random `JWT_SECRET` (at least 32 characters), `DATABASE_URL`, and exact frontend origins in `ALLOWED_ORIGINS`. Local HTTP uses `COOKIE_SECURE=false` and `COOKIE_SAME_SITE=lax`. HTTPS production uses secure cookies; an embedded cross-site Preview may require `COOKIE_SAME_SITE=none` and `COOKIE_SECURE=true` with the exact Preview origin allowed. `none` is rejected unless `COOKIE_SECURE=true`. Configure PostgreSQL TLS for your environment; the production pool requires certificate validation. From the repository root run `npm install`, `npm run db:migrate`, `npm test`, and `npm start`.

The migration runner applies sorted `.sql` files once and records them in `schema_migrations`. `GET /api/health` checks database readiness and returns HTTP 503 if PostgreSQL is unavailable. No default administrator credentials or demo activity are inserted. To bootstrap one superadmin and the first school, set `SUPER_ADMIN_EMAIL`, `SUPER_ADMIN_NAME`, `SUPER_ADMIN_PASSWORD` (12+ characters), `SCHOOL_NAME`, and `SCHOOL_SLUG` in the protected process environment and run `npm run admin:create` from the repository root. The operation stores a bcrypt hash, omits credentials from output, and seeds a domain-only education allowlist only when it creates the first school. Schools added through the API start with no policy rules. All unmatched sites remain denied. YouTube is not allowlisted: configure separate supported provider restrictions before enabling it. Do not expose public signup. `POST /api/users` creates an admin-managed account with an unusable random password hash; since email delivery and secure password setup are not implemented, an operator must provide account activation out-of-band.

## API contract

Cookie-authenticated JSON routes use `eduguard_session` by default. Obtain `csrfToken` via `GET /api/auth/csrf`, send it as `x-csrf-token` for unsafe cookie-authenticated requests, and keep the CSRF cookie intact. Login also sets the CSRF token in JSON. Login is rate limited; JWT is stored only in an HttpOnly cookie with configured SameSite/Secure attributes (defaults are `Lax` and insecure for local HTTP). Use `credentials: 'same-origin'` in browser fetches.

- `GET /api/health`; `GET /api/auth/csrf`; `POST /api/auth/login {email,password}`; `GET /api/auth/me`; `POST /api/auth/logout`.
- `GET /api/dashboard/summary`; `GET /api/activity?limit=&from=&to=&studentId=`; `GET|POST /api/students` (`POST {fullName,className?}`).
- `GET|POST /api/devices` (`POST {name,studentId,operatingSystem}` returns `{device,enrollmentCode}`); `PATCH /api/devices/:id/status {status}`.
- `GET|POST /api/rules` (`POST {kind:'website'|'application',domain/name,category,action:'allow'|'block',urlMatch:'domain',captureFullUrl:false}`); `DELETE /api/rules/:id`.
- `GET /api/notifications`; `PATCH /api/notifications/:id/read`; `GET /api/reports/trends?range=week|month`.
- `GET|POST /api/users` (admin-created accounts); `POST /api/relationships {role:'PARENT'|'TEACHER',userId,studentId,relationship?}` (SCHOOL_ADMIN only); `GET|POST /api/schools` (SUPER_ADMIN only).
- Extension `POST /api/extension/enroll {code,device:{name,os,extensionVersion}}` consumes a single-use short-lived code and returns `{deviceToken}`. `GET /api/extension/policy` and `POST /api/extension/activities/sync {events:[{eventId,domain,url?,applicationName?,occurredAt,durationSeconds,accessStatus,category}]}` require `x-device-token`. Events are deduplicated by `(device_id,event_id)`; the optional `url` is accepted for wire compatibility but deliberately never persisted.

School users are limited to their school. SUPER_ADMIN requests to school data endpoints must include `schoolId` query or body where applicable. Socket.IO authenticates the same session cookie: school administrators join their school room, while parents and teachers join only rooms for explicitly linked students. Successful device sync emits a content-free `activity:changed` event to those rooms; the browser refreshes applicable server-backed views and receives no domain or student details in the socket event.

Parents and teachers only see dashboard totals, activity, devices, notifications and students for accounts explicitly linked in `parent_students` / `teacher_students`; device assignment is not authorization. Parent and teacher school-wide settings, rules and user management are denied. `POST /api/relationships` and the administrator form accept only active same-school parent/teacher users and same-school students. `GET /api/extension/policy` returns `defaultAction:'deny'`, `captureFullUrl:false`, `websiteRules` (each has `id`, `domain`, `action`, `category`, and may include a legacy `urlMatch:'path'` label), and `applicationRules:[]` (plus a revision). The extension ignores path labels and matches domains/subdomains only. Exact/prefix URL filtering and application enforcement are not implemented. Sync does not persist submitted URLs; full-URL capture is always false.

## Operational cautions / remaining work

This project is not a completed or certified regulated product. Establish lawful basis, guardian/child notices and consent workflows, retention/deletion schedules, incident response, encrypted backups and Kenyan Data Protection Act review before deployment. Cross-table school consistency and explicit parent/teacher relationships are enforced by database/API checks. No alert generation, email delivery, account invitation activation/password reset, export/deletion workflow, billing lifecycle, or fabricated analytics are included. `restriction_policies` is stored but is not part of the extension response and does not trigger alerts. The MV3 extension is in `../extension/`; it applies only within an installed Chrome/Edge profile. Its IndexedDB queue handles offline retries and event IDs prevent duplicate inserts. Socket.IO's minimal `activity:changed` event triggers a client refresh; it contains no activity details. Live database execution and extension browser tests remain outstanding.

The trusted first-school bootstrap utility seeds a domain-only educational/AI allowlist; new schools created through `/api/schools` start with no rules. YouTube remains denied by default. Schools must configure a separate supported provider/browser integration for Restricted Mode before allowing it. Application blocking likewise requires a separate OS/MDM integration; the current extension does not provide it.
